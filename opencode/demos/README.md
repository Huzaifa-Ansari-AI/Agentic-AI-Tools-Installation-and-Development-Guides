# OpenCode Demos

This directory is for practical demonstrations of OpenCode workflows and capabilities.

## Purpose

The `demos/` directory contains:

- **Practical Examples** — Real-world use cases showing OpenCode in action
- **Documented Workflows** — Step-by-step walkthroughs of common tasks
- **Experimental Code** — Test projects to explore OpenCode features
- **Learning Resources** — Example projects for understanding best practices

## What This Directory Is NOT

This directory does **not** contain:

- Fabricated or fake examples
- Incomplete or broken code
- Marketing content or sales pitches
- Copy-pasted tutorials from elsewhere

Every demo should be:
1. **Practical** — Solves a real problem
2. **Documented** — Explains what it does and why
3. **Reproducible** — Can be run by following the steps
4. **Verified** — Actually works with OpenCode

## How to Create a Demo

When you're ready to add a practical demonstration:

1. **Create a folder** for your demo:

```
demos/
├── basic-code-review/
├── feature-implementation/
└── your-demo-here/
```

2. **Write a README** explaining:
   - What the demo shows
   - What problem it solves
   - How to run it
   - Expected results

3. **Keep it concise** — Focus on the core workflow, not extensive explanation

4. **Document the OpenCode conversation** if helpful — Show the actual commands used and results

## Current Structure

This directory is empty and ready for practical demos to be added.

## Suggested Demo Ideas

When you're ready to create demos, consider:

- **Code Review Workflow** — Using the Plan agent to review code
- **Feature Implementation** — Adding a new feature to an existing project
- **Refactoring Task** — Improving code quality in a specific file
- **Documentation Generation** — Creating README or API docs
- **Bug Investigation** — Finding and fixing issues with OpenCode's help

## Guidelines for Demo Projects

**Keep demos small and focused:**
- Single-feature projects, not full applications
- Reproducible within minutes, not hours
- Real code, not placeholder text

**Document every step:**
- Show the OpenCode commands used
- Explain the reasoning behind each step
- Note any limitations or edge cases

**Make it beginner-friendly:**
- Assume the reader is new to OpenCode
- Explain technical terms
- Provide clear before/after examples

## Running Demos

To use a demo:

1. Navigate to the demo directory:

```bash
cd demos/demo-name
```

2. Read the README for detailed instructions

3. Follow the documented workflow

4. Experiment and modify as needed
